@auth @smoke
Feature: Регистрация и авторизация
  Как пользователь
  Я хочу зарегистрироваться и войти в систему
  Чтобы получить доступ к функционалу платформы

  Background:
    Given система доступна
    And база данных пуста

  @positive
  Scenario: Успешная регистрация нового пользователя
    Given пользователь открывает страницу регистрации
    When пользователь вводит:
      | Поле         | Значение                |
      | username     | test@example.com        |
      | email        | test@example.com        |
      | password     | SecurePass123           |
      | password2    | SecurePass123           |
      | first_name   | Иван                    |
      | last_name    | Иванов                  |
    And пользователь нажимает "Зарегистрироваться"
    Then система создает учетную запись
    And пользователь получает роль "CLIENT"
    And система возвращает данные пользователя
    And статус ответа 201

  @negative
  Scenario: Регистрация с уже существующим email
    Given в системе уже зарегистрирован пользователь test@example.com
    When пользователь пытается зарегистрироваться с email test@example.com
    Then система возвращает ошибку 409
    And сообщение: "Пользователь с таким email уже существует"

  @positive
  Scenario: Успешная авторизация
    Given пользователь зарегистрирован в системе
    When пользователь вводит:
      | Поле     | Значение         |
      | username | test@example.com |
      | password | SecurePass123    |
    And нажимает "Войти"
    Then система возвращает access и refresh токены
    And статус ответа 200

  @negative
  Scenario: Авторизация с неверным паролем
    Given пользователь зарегистрирован в системе
    When пользователь вводит неверный пароль
    Then система возвращает ошибку 401
    And сообщение: "Неверный email или пароль"

  @positive
  Scenario: Обновление токена
    Given пользователь авторизован в системе
    When пользователь отправляет refresh токен
    Then система возвращает новый access токен
    And статус ответа 200

# МОДУЛЬ 2: CHAT (AI-АГЕНТ)
# ============================================

@chat @ai @smoke
Feature: AI-чат для оформления перевозки
  Как клиент
  Я хочу общаться с AI-ассистентом
  Чтобы быстро оформить заявку на перевозку

  Background:
    Given пользователь авторизован в системе
    And пользователь открыл чат

  @positive
  Scenario: Полное распознавание параметров из одного сообщения
    Given пользователь вводит сообщение:
      """
      Нужно перевезти 500 кг оборудования из Москвы в Санкт-Петербург завтра
      """
    When система обрабатывает сообщение
    Then система распознает все параметры:
      | Параметр       | Значение            |
      | ship_from      | Москва              |
      | ship_to        | Санкт-Петербург     |
      | cargo_type     | equipment           |
      | weight_kg      | 500                 |
      | shipment_date  | 2026-07-27          |
    And система выполняет поиск тарифов
    And система возвращает список вариантов
    And need_clarification = false

  @positive
  Scenario: Частичное распознавание с уточнением
    Given пользователь вводит сообщение: "Перевезти груз из Москвы"
    When система обрабатывает сообщение
    Then система распознает только ship_from
    And система запрашивает недостающие параметры
    And need_clarification = true
    And сообщение содержит вопросы о городе назначения, весе и типе груза

    When пользователь отвечает: "В Санкт-Петербург, 500 кг, оборудование"
    Then система распознает все параметры
    And выполняет поиск тарифов

  @negative
  Scenario: Пустой запрос
    Given пользователь вводит пустое сообщение
    When система обрабатывает сообщение
    Then система возвращает сообщение: "Пожалуйста, опишите вашу перевозку"
    And need_clarification = true

  @negative
  Scenario: Нераспознаваемый запрос
    Given пользователь вводит сообщение: "Привет"
    When система обрабатывает сообщение
    Then система не может определить ни один параметр
    And система запрашивает все обязательные параметры
    And сообщение содержит список всех обязательных параметров

  @error
  Scenario: Ошибка при обработке сообщения
    Given AI-сервис временно недоступен
    When пользователь отправляет сообщение
    Then система возвращает сообщение: "Сервис временно недоступен. Попробуйте позже"
    And статус ответа 500

# МОДУЛЬ 3: ПОИСК ТАРИФОВ
# ============================================

@tariffs @smoke
Feature: Поиск тарифов
  Как клиент
  Я хочу искать доступные тарифы
  Чтобы выбрать лучший вариант перевозки

  Background:
    Given пользователь авторизован в системе
    And в системе есть активные тарифы

  @positive
  Scenario: Успешный поиск тарифов
    Given пользователь указывает параметры поиска:
      | Параметр       | Значение            |
      | ship_from      | Москва              |
      | ship_to        | Санкт-Петербург     |
      | cargo_type     | equipment           |
      | weight_kg      | 500                 |
    When пользователь отправляет запрос на поиск
    Then система возвращает список тарифов
    And каждый тариф содержит:
      | Поле              |
      | id                |
      | carrier           |
      | price             |
      | delivery_days_min |
      | delivery_days_max |
    And результаты отсортированы по цене (от дешевых к дорогим)

  @positive
  Scenario: Поиск с неполными параметрами
    Given пользователь указывает только обязательные параметры:
      | Параметр  | Значение        |
      | ship_from | Москва          |
      | ship_to   | Санкт-Петербург |
      | weight_kg | 500             |
    When пользователь отправляет запрос на поиск
    Then система возвращает тарифы с любым типом груза
    And система возвращает тарифы с любым типом доставки

  @negative
  Scenario: Тарифы не найдены
    Given пользователь указывает параметры без тарифов
    When пользователь отправляет запрос на поиск
    Then система возвращает ошибку 404
    And сообщение: "По вашему маршруту нет доступных перевозчиков"
    And предложение: "Попробуйте изменить дату или вес груза"

  @negative
  Scenario: Поиск без обязательных параметров
    Given пользователь не указал ship_from
    When пользователь отправляет запрос на поиск
    Then система возвращает ошибку 400
    And сообщение: "Не указаны обязательные параметры"

# МОДУЛЬ 5: ОПЛАТА ЗАКАЗА
# ============================================

@payments @smoke
Feature: Оплата заказа
  Как клиент
  Я хочу оплатить заказ
  Чтобы подтвердить перевозку

  Background:
    Given пользователь авторизован в системе
    And заказ создан со статусом "created"

  @positive
  Scenario: Успешная оплата заказа
    Given пользователь открывает страницу оплаты
    When пользователь оплачивает через платежный сервис
    Then система получает подтверждение оплаты
    And статус платежа меняется на "paid"
    And статус заказа меняется на "paid"
    And пользователь получает уведомление об оплате

  @negative
  Scenario: Ошибка при оплате
    Given пользователь открывает страницу оплаты
    When платеж не проходит (недостаточно средств)
    Then статус платежа меняется на "failed"
    And статус заказа остается "created"
    And пользователь получает сообщение об ошибке

  @negative
  Scenario: Истечение времени оплаты
    Given заказ создан
    And прошло 2 часа с момента создания
    When система проверяет статус оплаты
    Then заказ автоматически переходит в статус "expired"
    And пользователь получает уведомление

# МОДУЛЬ 6: УПРАВЛЕНИЕ ЗАКАЗАМИ
# ============================================

@orders @management
Feature: Управление заказами
  Как клиент
  Я хочу просматривать и управлять заказами
  Чтобы отслеживать статус перевозки

  Background:
    Given пользователь авторизован в системе
    And у пользователя есть несколько заказов

  @positive
  Scenario: Просмотр истории заказов
    When пользователь открывает раздел "Мои заказы"
    Then система отображает список всех заказов
    And каждый заказ содержит:
      | Поле              |
      | order_number      |
      | status            |
      | price             |
      | ship_from         |
      | ship_to           |
      | created_at        |
      | expected_delivery |

  @positive
  Scenario: Фильтрация заказов по статусу
    When пользователь выбирает фильтр "in_transit"
    Then система отображает только заказы в пути
    And количество заказов соответствует фильтру

  @positive
  Scenario: Просмотр деталей заказа
    Given пользователь открывает конкретный заказ
    Then система отображает полную информацию:
      | Раздел      | Содержание                     |
      | Информация  | Номер, статус, дата создания   |
      | Маршрут     | Откуда, куда, дата отправки    |
      | Груз        | Тип, вес, габариты             |
      | Перевозчик  | Название, телефон, рейтинг     |
      | Оплата      | Статус, сумма, дата оплаты     |
      | История     | Все изменения статуса          |

  @positive
  Scenario: Отмена заказа до оплаты
    Given заказ в статусе "created"
    When пользователь нажимает "Отменить заказ"
    And подтверждает отмену
    Then статус заказа меняется на "cancelled"
    And заказ сохраняется в истории

  @positive
  Scenario: Отмена оплаченного заказа
    Given заказ в статусе "paid"
    When пользователь нажимает "Отменить заказ"
    And подтверждает отмену
    Then статус заказа меняется на "cancelled"
    And инициируется возврат средств
    And статус платежа меняется на "refunded"

  @negative
  Scenario: Отмена заказа в статусе "in_transit"
    Given заказ в статусе "in_transit"
    When пользователь пытается отменить заказ
    Then система возвращает ошибку
    And сообщение: "Заказ нельзя отменить в текущем статусе"

@admin @management
Feature: Управление перевозчиками и тарифами
  Как администратор
  Я хочу управлять перевозчиками и тарифами
  Чтобы поддерживать актуальные данные системы

  Background:
    Given администратор авторизован в системе
    And у администратора есть права ADMIN

  @positive
  Scenario: Создание нового перевозчика
    When администратор заполняет данные перевозчика
    And отправляет запрос на создание
    Then перевозчик создается в системе
    And перевозчик активен по умолчанию

  @positive
  Scenario: Отключение перевозчика
    Given перевозчик существует и активен
    When администратор отключает перевозчика
    Then is_active = false
    And перевозчик не участвует в поиске тарифов

  @positive
  Scenario: Создание нового тарифа
    When администратор заполняет данные тарифа
    And отправляет запрос на создание
    Then тариф создается в системе
    And тариф активен по умолчанию

  @positive
  Scenario: Отключение тарифа
    Given тариф существует и активен
    When администратор отключает тариф
    Then is_active = false
    And тариф не участвует в поиске

  @negative
  Scenario: Создание дублирующего тарифа
    Given тариф с такими параметрами уже существует
    When администратор создает тариф с теми же параметрами
    Then система возвращает ошибку 409
    And сообщение: "Тариф с такими параметрами уже существует"

# МОДУЛЬ 8: СКВОЗНЫЕ СЦЕНАРИИ
# ============================================

@e2e @critical
Feature: Полный процесс оформления перевозки (E2E)
  Как клиент
  Я хочу пройти полный цикл оформления перевозки
  Чтобы получить готовый заказ

  Scenario: Полный цикл от запроса до оплаты
    Given пользователь не авторизован
    When пользователь регистрируется
    Then пользователь успешно зарегистрирован

    When пользователь вводит в чат: "Москва → Казань, 200 кг, мебель, послезавтра"
    Then система распознает параметры
    And показывает варианты перевозки

    When пользователь выбирает тариф
    Then система создает заказ со статусом "created"

    When пользователь переходит к оплате
    And успешно оплачивает заказ
    Then статус заказа меняется на "paid"
    And пользователь получает уведомление
